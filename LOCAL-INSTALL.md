# Local Codex auto reply

The installed runtime is ~/Library/Application Support/Petroglyphs. The launch agent is ~/Library/LaunchAgents/local.petroglyphs.plist. Build source changes before copying dist into the runtime.

PETROGLYPHS_AUTO_REPLY_CONFIG points to a private JSON file containing deviceToken (32+ hex characters), codexPath (absolute), and dataDir (absolute). The legacy threadId setting is optional and is no longer a default target.

The iPad Local URL is http://MAC_IP:3333/device/TOKEN. Only this private route triggers Codex. The ordinary base URL still uploads without triggering a reply. Use a trusted LAN and keep the token private.

Updated iPad installations support wireless discovery and pairing. Keep Tailscale connected on the iPad and Mac, select an available Mac bridge, compare the six-digit code, and approve in the Mac's local browser window. The app obtains the existing private URL through an encrypted pairing response. Manual URL entry is an advanced compatibility option.

The app installer supplies a token-free MagicDNS seed and an HTTP exception scoped to that tailnet's DNS suffix. Generate its plist using the app repository's `scripts/configure-discovery.py`. No Tailscale administrator credential is embedded in the app. The seed bridge must be reachable on a fresh installation. Each additional discoverable Mac must run this compatible bridge on the same configured port. Bonjour also advertises `_petroglyphs._tcp` for local discovery; `PETROGLYPHS_BONJOUR=0` disables that advertisement.

`GET /api/bridge/discovery` and `/api/bridge/pairings` are explicit token-free enrollment routes, including when `PETROGLYPHS_REQUIRE_DEVICE_AUTH=1`. They do not expose chats, settings, bearer tokens, or Tailscale user details. The directory probes only online macOS peers from the local Tailscale daemon. It validates each peer at that peer's IP before using its daemon-provided MagicDNS name. Pairing uses P256, HKDF-SHA256 and AES-256-GCM. The confirmation code derives from the session key. A loopback-only Mac approval with a separate capability is required before credentials become available. Pending requests expire after five minutes. Origin, Host, source and rate limits apply. Approval pages use `Referrer-Policy: same-origin`; the protocol endpoints retain `no-referrer`.

The iPad-to-bridge network route is independent of the Codex execution destination. A Tailscale connection to this bridge can still select a separate Codex Remote Connection. Discovery and pairing do not install or enable a remote Codex connection.

The private GET /api/codex/hosts endpoint returns the local Mac and remote connection summaries. With PETROGLYPHS_CODEX_DESKTOP=1, saved enabled Remote Connections with a complete Desktop chat directory can be selected directly. `available` means the connection can be attempted, not that the remote machine is currently online. Configured helpers remain a fallback. See DIRECT-REMOTE.md for the direct Desktop configuration.

With Desktop routing enabled, the paired conversation API also supports complete user/assistant history, plain text and multiple images for local and Remote Connection chats. See [CONVERSATION-API.md](CONVERSATION-API.md) for its fixed-target requests, durable idempotency, safe image assets and recovery rules. New conversations use `dataDir/conversations`; legacy drawing receipts remain in their existing directories. This API requires Desktop access and does not fall back to a different host or helper when delivery is uncertain.

The private GET /api/codex/threads endpoint accepts optional search, cursor, and hostId parameters. hostId defaults to local. It returns non-archived Codex chats as {threads: [{id, title, cwd, updatedAt}], nextCursor}. updatedAt is a Unix timestamp in seconds. Local chats use a short-lived codex app-server stdio connection and thread/list. Direct remote chats use Desktop's maintained full directory, with title/path search and host-bound pagination. It returns metadata only. Ordinary URLs cannot read this list.

Private POST /api/submit requires an explicit threadId and accepts an optional hostId (default local). It checks the selected directory before saving. A direct remote target saves a durable PNG and receipt under dataDir/remote-desktop, then sends image bytes through Desktop IPC and the existing Remote Connection. It never sends the Mac's local image path as a remote path. A helper target retains the earlier authenticated forwarding behavior and owns its receipt remotely. The receipt contains id, threadId, hostId, and status: received. Ordinary uploads keep the original upload-only behavior; an ordinary upload containing a Codex target is rejected.

Each image gets its own durable PNG and JSON receipt, including the target selected when Send was tapped. Local sends use codex queue with the exact saved image path and view_image. Direct remote sends use PNG image input. Later selection changes do not retarget queued images. Direct remote jobs wait while the selected chat is busy; local/helper jobs use the Codex queue. Pending jobs resume after a service restart. An uncertain dispatch is never automatically replayed.

Queue admission states are pending, dispatching, queued, and unknown. Queued proves CLI admission, not a completed response. Failed or interrupted dispatches are not automatically retried because the CLI might already have accepted the message. Inspect the chat before retrying. Saved files are retained until manually removed.

The private GET /api/codex/submissions/:id endpoint returns only a known device submission. Pass the receipt's hostId as a query parameter for remote submissions. Its response contains id, threadId, hostId, state, messages, and optional error, notice, and coalescedSubmissionIds. A queued receipt remains queued until the exact submission marker appears in a Codex userMessage. A matched turn can become running, completed, or failed. Completed responses and their turn IDs are saved with the receipt.

To restore cards after an app restart, call private GET /api/codex/submissions?threadId=THREAD_ID&hostId=HOST_ID. It returns {submissions: [{id, threadId, hostId, createdAt}]} for the newest 20 known receipts in that chat. createdAt is an ISO 8601 timestamp. This reads the device ledger and exposes no image paths or arbitrary Codex history. Continue with GET requests for those receipt IDs; recovery does not submit another image.

Reply messages are complete snapshots containing id, text, and phase (commentary, final_answer, or unknown for older messages). Only public assistant messages after the associated input are returned. Tools and reasoning are omitted. Several device submissions in one turn share an explicitly marked response. Other user input in that turn produces an unknown state with a notice, rather than displaying a potentially unrelated answer. Explicit failed turns produce safe error descriptions. The separate stdio reader can report an active desktop turn as interrupted, so that observation returns unknown with an awaiting-confirmation notice and remains pollable. The known old interrupted-failure cache is migrated to unknown on load or read, preserving its receipt, turn ID, and image. The reader also cannot reliably observe the desktop process's pending approval flags.

Poll replies every three seconds, and back off when the status is unchanged or retrieval fails. Concurrent polls for one receipt share a lookup. Successful lookups are cached for at least three seconds. Completed and failed responses use the durable cache. Unknown is not necessarily terminal: an uncertain queue admission can still be matched later. A 404 means this device has no such receipt; a 503 is a temporary retrieval error. Do not automatically resubmit an image after a network timeout.

For a dedicated remote helper, set PETROGLYPHS_BIND_HOST to its private Tailscale address and PETROGLYPHS_REQUIRE_DEVICE_AUTH=1. This rejects unpaired requests before landing, MCP, or upload routes. The existing local listener keeps its original defaults when those settings are absent.

Disable by using the ordinary iPad base URL, or remove PETROGLYPHS_AUTO_REPLY_CONFIG and restart the service.

Run npm run build, then the relevant tests. Compiled-code tests use node tests/auto-reply.mjs, node tests/replies.mjs, node tests/remote-routing.mjs, and node tests/desktop-submissions.mjs. TypeScript-source tests use node --import tsx tests/desktop-catalog.mjs, tests/desktop-ipc.mjs, or tests/remote-hosts.mjs. HTTP/Unix-socket tests need local socket permissions. Real iPad upload and an observed response from the selected remote chat remain the end-to-end acceptance gate.
